## 再現可能なセットアップと範囲を限定した設定

```sh
# 使い捨ての clone／worktree で、認可を得た後に実行:
claude --version                 # 確認した版を記録する
claude login                     # または認可済みアカウントを使う
claude                           # fixture ディレクトリから開始する
```

ツールの操作を受け入れる前に、権限確認の内容を確認してください。現行版が提供する最小権限から始め、未レビューの設定をコピーせず、文書化された permissions／settings の仕組みを使います。外部通信、デプロイ、資格情報、破壊的操作、worktree 外への操作は拒否します。短いセッション期限、修正は最大 2 回、学習者が承認した費用上限を設定します。可能なら `/cost` を使い、表示された提供者／モデル／費用を秘密情報なしで記録します。権限フラグや設定名は版によって変わります。上記の公式 permissions／settings ページに従い、実際に選んだ内容を記録してください。

## 使い捨て演習

`projects/claude-code-disposable/` を一時ディレクトリまたは worktree にコピーします。エージェントには小さなバグ報告、`src/greeter.py`、`tests/test_greeter.py` だけを渡し、`src/greeter.py` だけを変更するよう指示します。fixture には意図的に失敗するテストがあります。エージェントはまず失敗を観察し、最小の変更を加え、テストを実行して終了コードを報告しなければなりません。その後、学習者が自分でテストを実行し、`git diff --check` と `git diff` を確認し、`src/greeter.py` 以外のファイル変更は却下します。2 回目のプロンプトでは、意図的に誤った最初の結果（期待される挨拶文は大文字・小文字を区別する）を修正させ、失敗した結果と修正後の結果の両方を記録します。

必須のローカル証拠コマンド:

```sh
cd projects/claude-code-disposable
python3 verify_fixture.py
```

公開されている検証スクリプトは一時的な Git リポジトリを作り、意図的な失敗テストを記録し、範囲を限定した大文字化の修正だけを適用し、テストを再実行し、`git diff --check` と変更パス一覧を確認します。実際に Claude Code を使った場合は、ツール終了後に同じコマンドを自分で実行してください。検証スクリプトは決定的な代替手段にすぎません。

最初のコマンドは**決定的な代替手段**であり、Claude Code が実行された証明ではありません。認可が得られないときに役立ちます。`docs/evidence/claude-code/` にあるサニタイズ済みの成果物は文書／fixture の証拠にすぎず、実ツールの記録として提示してはいけません。実際の実行が受け入れられるのは、実際の Claude Code の版、選んだ提供者／モデル、権限の判断、費用（またはプラン／割当枠）、失敗、修正、独立したテスト出力、レビュー済みの差分を示す、秘匿処理済みの記録またはコマンドログを学習者が提出した場合だけです。API キー、アカウント識別子、秘密情報を含むプロンプト内容、外部への副作用は決して含めないでください。
