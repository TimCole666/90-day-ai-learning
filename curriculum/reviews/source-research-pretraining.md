# Source research: pretraining (b08, Days 49–60)

## Decision
**Recommend CS336 Assignment 1 (Spring 2025) as the lead implementation/exercise source, with nanoGPT retained as a historical, compact loop-reading reference.** This is an evidence-based internal recommendation, not independent expert review. CS336’s repo exposes a student assignment handout, `NotImplementedError` adapters, and targeted tests; its Spring 2025 archived release is later than the currently registered Spring 2024 repository. nanoGPT’s own README explicitly says (Nov 2025) it is “very old and deprecated” and points readers to nanochat. nanochat is current and broad, but its pretraining implementation is substantially more optimized and complex than a first loop walkthrough.

CS336 source: [Spring 2025 release](https://github.com/stanford-cs336/assignment1-basics/releases/tag/spring2025), [README](https://github.com/stanford-cs336/assignment1-basics/blob/spring2025/README.md), [assignment handout](https://github.com/stanford-cs336/assignment1-basics/blob/spring2025/cs336_spring2025_assignment1_basics.pdf), [tests](https://github.com/stanford-cs336/assignment1-basics/tree/spring2025/tests), [CHANGELOG](https://github.com/stanford-cs336/assignment1-basics/blob/spring2025/CHANGELOG.md). README says run `uv run pytest`; tests initially fail with `NotImplementedError`. Specific targets: `tests/adapters.py` contracts for `get_adamw_cls`, `run_get_lr_cosine_schedule`, `run_gradient_clipping`, `run_save_checkpoint`/`run_load_checkpoint`; `tests/test_optimizer.py::test_adamw` and `test_get_lr_cosine_schedule`; `tests/test_nn_utils.py::test_gradient_clipping`; `tests/test_serialization.py::test_checkpointing`. Changelog confirms explicit fixes/clarifications for global gradient norm and checkpoint tests. These are practice/checks, not a complete end-to-end production training loop. The Spring 2025 repo has an actual MIT LICENSE; verify that tag’s LICENSE before recording the registry as linking-only/no license. Spring 2024 URL remains valid, but its README is older and setup differs.

## Code mapping and constraints
- **Day 50 optimizer and schedule:** CS336 `tests/adapters.py` contracts + optimizer tests; compare with nanoGPT [`GPT.configure_optimizers`](https://github.com/karpathy/nanoGPT/blob/master/model.py) (AdamW parameter groups) and [`get_lr`](https://github.com/karpathy/nanoGPT/blob/master/train.py) (linear warmup, cosine decay). nanoGPT also provides a compact concrete reference for clipping (`clip_grad_norm_`) in `train.py`’s training loop.
- **Day 51 training loop / Day 55–57 checkpointing:** nanoGPT `train.py` `estimate_loss`, training loop, resume initialization, and checkpoint payload; `sample.py` reads that checkpoint. CS336’s `test_serialization.py::test_checkpointing` checks restored model and optimizer state plus iteration, but does not teach robust atomic writes, corruption fallback, cloud preemption, or complete RNG/dataloader-state recovery. Keep course-specific extensions for those.
- **Day 52 decoding:** nanoGPT `GPT.generate` and `sample.py` demonstrate temperature and top-k, **not nucleus/top-p**. Do not cite these as coverage of top-p.
- **Day 56/58–60 compute and real-world operations:** nanochat README sections “Time-to-GPT-2 Leaderboard,” “Running on CPU / MPS,” “Precision / dtype,” plus `scripts/base_train.py` scaling/horizon and telemetry code give a current systems reference. The headline speedrun is explicitly designed for an 8×H100 node; `runs/runcpu.sh` is a deliberately shrunk educational demo and says to expect weak results. Do not imply CPU toy runs reproduce serious pretraining results. nanoGPT README similarly distinguishes a small CPU Shakespeare demo from GPT-2 reproduction requiring at least 8×A100 40GB. nanochat’s `scripts/base_train.py` has no `clip_grad` locator in the inspected current source; it is not a direct replacement for nanoGPT/CS336 clipping instruction.
